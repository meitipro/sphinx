## What reaches the model

- At most 10 answers per call: the next revealed, unjudged answers in seal order, cut inside the contract, so every validator judges the same ten.
- An answer that is empty once flattened is "no answer at all": labelled `WRONG` by code, never sent.
- A seal never opened never reaches the judge. It is `UNREVEALED` at settlement.
- Answers are cut to 80 characters when revealed.

## How validators agree

Each validator labels the batch itself and agrees only when the set of answers it labels `CORRECT` is the leader's. That set is the only thing that moves money. The leader's split between `CLOSE` and `WRONG` is stored for display; both are paid the same, nothing, so a disagreement over a near miss never stalls a batch and never changes who is paid.

An answer the contract cannot read as one label per answer, in order, is retried once, then fails the round. It never becomes a label. A round where the validators' models disagree on the `CORRECT` set stores nothing: the batch stays waiting, and anyone may send `judge` again.

## What is never asked

Winners, ranks, shares, fees, refunds and every window are contract code. The prompt never mentions money, order or time, and a test fails if it does.
